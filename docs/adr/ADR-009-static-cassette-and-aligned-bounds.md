## ADR-009: Перевод марковского оракула на статическую кассету памяти с выравниванием по границам циклов

**Статус:** Принято к реализации  
**Командир дев-группы «Альфа»:** Капитан Алёхин  
**Аналитик:** Старлей Женя  

### 1. Архитектурная уязвимость текущей схемы
Использование `Buffer.concat` на каждой итерации цикла расширения `for (let i = 0; i < 128; i += 16)` генерирует скрытые аллокации в куче V8, провоцируя фрагментацию памяти и холостые циклы сборщика мусора (GC). 

### 2. Целевое решение (Концепция статической кассеты)
Вместо динамического доращивания буфера в цикле, рабочий объем памяти выделяется **единожды** на входе в марковский движок (или берется из предвыделенного пула ядра). Размер кассеты жестко привязывается к верхнему лимиту безопасности цикла защиты от бесконечного чтения: `MAX_ALLOWED_SIZE = 128` байт.

### 3. Инвариант кратных шагов и адресации
Переменная цикла `i += 16` преобразуется из счетчика аллокаций в **строгий курсор-ограничитель (Scope Boundary)** физической видимости данных.

* **Чтение источника:** На каждом такте инструкция `buffer.copy` заполняет строго отведенный сектор кассеты:
  ```javascript
  // Копируем очередное 16-байтное окно, не затрагивая голову буфера
  n = buffer.copy(tmp, oldLength, index + oldLength, index + i + 16);
  ```
* **Ограничение НАМ:** Функция поиска совпадений `cmpTmpToRule` и перезаписи ограничивает свой операционный радиус текущей виртуальной длиной буфера `(i + 16)`. Всё, что находится за пределами этой границы, игнорируется процессором.
* **Защита памяти:** Если цикл достигает терминального индекса `i = 128`, а легальный марковский маркер конца ячейки (`0x03`) не обнаружен, автомат считает структуру поля нарушенной (уязвимость незакрытой строки). Происходит аварийный останов с кодом ошибки `ERR_FIELD_TOO_LONG`.

### 4. Влияние на железо фон Неймана
Размер блока (16 байт) и максимальная граница (128 байт) идеально выровнены по степеням двойки (\(2^4\) и \(2^7\)), что исключает промахи кэша процессора (L1/L2 Cache Misses) и оптимизирует побайтовое сравнение на уровне регистров ЦП. Накладные расходы на управление памятью падают до абсолютного нуля (*Zero-Overhead*).
