Для достижения истинного Zero-Overhead по процессору необходимо оптимизировать функцию поиска марковских правил `cmpTmpToRule` в `lib/parser/markov/parse_escaped_byte.js`. Текущая реализация при добавлении каждых новых 16 байт сканирует буфер `tmp` с нулевого индекса, что порождает квадратичные накладные расходы ЦП.

Необходимо ограничить зону поиска исключительно свежеприбывшим 16-байтным чанком данных.

## Математический инвариант и требования
Для исключения пропуска марковских коллизий на стыках окон (например, если пара кавычек `""` разорвана границей чанка), поиск должен начинаться строго с формулы:
$$start\_search\_index = \max(0, oldLength - 1)$$

* **Входные параметры:** Функция `cmpTmpToRule` обязана принимать новый параметр — `start_index`.
* **Ограничение конвейера:** Внутренний цикл поиска `for` в `cmpTmpToRule` инициализируется значением `let i = start_index` вместо `0`.
* **Результат:** Процессор полностью игнорирует уже обработанную, стабильную "голову" буфера, проверяя только 1 пограничный байт из прошлого такта и свежие 16 байт. Сложность операции падает до $\Theta(1)$.

## Критерии приемки
1. Функция `cmpTmpToRule` переведена на локальный поиск со смещением.
2. Тест-кейс `zero me why ""you lied to me"" ",` со вложенными кавычками на стыках успешно проходит разбор.
