## Описание задачи
Для окончательного подтверждения пуленепробиваемости марковского оракула и практического решения проблемы останова на случайных данных необходимо развернуть изолированный Property-Based (стохастический) тестовый полигон без привлечения внешних библиотек.

## Инженерные требования и проверяемые свойства (Инварианты)
1. **Генератор хаоса:** Написание генератора случайных буферов с двумя режимами: полный битовый хаос (`[0x00..0xFF]`) и "марковский шторм" (случайные скопления кавычек `0x22`, запятых `0x2C` и пробелов).
2. **Инвариант Терминальности (Watchdog):** Контроль времени выполнения одного прохода. Если алгоритм тратит на буфер до 200 байт более 50 мс — фиксируется бесконечный цикл подстановок НАМ.
3. **Инвариант Монотонности:** Проверка строгого движения указателя `next_index` только вперед при успешном разборе.
4. **Инвариант Границ Кассеты:** Контроль жесткого отсечения полей, превышающих лимит `capacity = 128`.

## Критерии приемки
* Скрипт `lib/parser/markov/property_test.js` успешно выполняет 5000 тактов случайной бомбардировки ядра.
* Ни один стохастический буфер не приводит к зависанию, падению по границам памяти или нарушению логики Хоара.
